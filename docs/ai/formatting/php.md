# PHP (`lang-php`)

## Parser
mago-syntax (PHP 8.0 to 8.4 and the 8.5 syntax it knows: property hooks, asymmetric visibility, the pipe operator, `(void)`; a hand-written parser, pinned `=1.59.0` with its helper crates, bumped by hand: a release newer than 1.59.0 needs a newer rustc) behind `crates/lang-php/src/adapter.rs`. mago's lexer gives every token of the file (inline HTML, `<?php`/`<?=`/`?>`, the parts of interpolated strings and heredocs); the adapter drops whitespace and comments, which `provider_api::adapter::replay` rebuilds from the text between tokens ([../architecture/adding-a-language.md](../architecture/adding-a-language.md)). mago's CST gives the node spans in one walk: `grammars/php.grammar` has a row per struct of the CST, none for its enum wrappers (`Statement`, `Expression`, `Hint`, ...) or its one-token nodes (`Keyword`, names), which are tokens of the parent. Only `mago-syntax` and the crates it needs are dependencies (`third_party/mago-reporting` and `third_party/mago-php-version` replace two of them through `[patch.crates-io]`: the originals pull in schemars with `preserve_order`, which reorders every `serde_json` map of the build, the CLI's JSON output and the schema files among them; the first is the `Issue` builder mago-syntax uses, the second the original without the derive) (`mago-formatter`, `mago-linter` and `mago-analyzer` are not: layout and rules are ours). A parser panic is a parse error and the file stays as written. A syntax error loses the statement it is in (a class is one statement), so the error is reported but the tree is coarse.

Files: `*.php`, `*.phtml`, `*.inc`.

## Formatting
Layout of PHP-CS-Fixer's `@PER-CS` rule set, as data: `crates/lang-php/format.rules` is the whole formatter and `PhpFormatter` is `core_format::rules::LazyRules` over it. The file has the sections of the shared kit: `[space]`, `[joined]`, `[at_least_one]`, `[op_first]` (token spacing), `[rewrite]` (code rewrites), `[flow]`, `[comments]`, `[file]`, `[blank]` and `[layout]` (node layouts). The PHP tree is flat (most of `grammars/php.grammar` is `#opaque`), so a node with no `[layout]` row is `shapes::flow::Flow`: its children one after the other, the blanks between two tokens a `[space]` row (any other pair keeps the blanks of the source), a line break the source has stays one, and the lines after the first hang below the line the node starts on by as many columns as the source indents them. Blank lines (as many as the source has) and comments stay where they are. `[layout]` rows put blocks, class bodies, `switch` and `match` bodies, argument and parameter lists and alternative-syntax bodies (`if (...):` ... `endif;`) on the kit's shapes: a list the source breaks has one item per line and a trailing comma (option `trailing_commas`; not after a variadic parameter), a list on one line stays on one line. The brace of a class, function or method is on its own line (`declaration_brace`), a function with a multi-line parameter list has it on the line of the `)`. An array keeps its layout and gets a trailing comma when its `]` is on a line of its own. Interpolated strings, heredocs and shell strings are printed as written, and so is a file with inline text (`?>` followed by HTML) or of one line.

Rewrites (`[rewrite]` rows, before the layout; the result is parsed again): `array(...)` to `[...]`, `new Foo` to `new Foo()`, `public` for a class member without visibility (`var` too).

Parity (`scripts/parity.sh format php-cs-fixer`, PHP-CS-Fixer 3.95.31, `@PER-CS`, the corpus of the Conformance section): identical on 9,185 of 10,382 files (88.5 percent; 13 percent with the formatter that kept files as written), `second-format` 0, refused 0 (PHP-CS-Fixer rejects 7 files). Named gaps, by number of files: files with inline text (about 790 with a `?>`: PHP-CS-Fixer formats the PHP islands, we keep the file as written); one `use` per trait (`use A, B;` split, 77) and a blank line after `<?php` before a leading comment (26): rewrites that insert text the rows cannot yet (W1); `case x: stmt;` on one line and the `// no break` comment (14); attributes on parameters of a multi-line parameter list go on their own line (20); a comment after an operator at the end of a line (10); `null` last in union types, the final `?>` of a pure PHP file, `else if` to `elseif`, braces for the body of a control structure, modifier order and import order are not rewritten.

## Conformance
`tests/conformance/fetch-php-corpus.sh` fetches Laravel, Symfony (with its test fixtures), WordPress and Composer at pinned commits (10,389 `.php` files, 100 MB): every file parses without error, prints back byte for byte and formats with the same tokens and idempotently (`cargo test --profile corpus -p lang-php --test integration -- --ignored --nocapture conformance`, 29 s). A file that ends in inline text (a template with no closing PHP block) keeps its end exactly: the formatter says so through `NodeFormatter::exact_end`, so no final newline is added.

## Lint
`undefined-variable` (on; PHPStan level 0, [../parity/phpstan.yaml](../parity/phpstan.yaml)) is the shared scope rule on `scope.rows`, PHP's table (`globals/php.txt`: `$this` and the superglobals): a variable is declared by its first write in its function (assignment, `list`, `foreach`, `catch`, `global`, `static`, a parameter, `use`; `use (&$x)` also writes the variable of the function around the closure), a function sees none of the names around it (an arrow function sees them), and a read with no write anywhere in the function is reported. Not decided, so not reported: a variable passed to a call (it may be taken by reference), named by `isset`, `empty`, `unset` or a static property, `$this` and the superglobals, anything at the top level of a file (an including file may define it), and every function that uses `extract`, `parse_str`, `include`, `require`, `eval` or `$$name`.
