# Known bugs

Open bugs only, one entry each: symptom, cause, suggested fix. The commit that fixes a bug deletes its entry.

- **`lsp` test `a_cancelled_pull_is_answered_with_request_cancelled` flakes under load** (`crates/lsp/tests/responsiveness.rs`, `#[ignore]` until fixed). Symptom: fails when other builds load the machine, passes alone (about 2,800 runs alone did not reproduce it). Cause: not found. The test assumes the server has read both `$/cancelRequest` notifications before it answers the `format` sent after them; under load that ordering may not hold. Suggested fix: confirm by logging the order the loop reads messages in, then make the test wait for an observable point (or make the loop drain pending notifications before answering a request), and remove the `#[ignore]`.
- **JS `undefined-variable` (off)**: it knows only ES builtins (as ESLint without `env`), so `console`, `window`, `expect`, `btoa` are reported (108 per 10k lines on the corpus). Fix: an `environments` option (`browser`, `node`, `test`) with globals data files, default on for all three; the browser set alone is about 700 names, so it is a data task of its own.
- **First active rule costs about 5M instructions per bench input in protobuf** (lint 532,677 with no rule on, 5,477,200 with `enum-first-value-zero`): engine setup (rule compilation, traversal dispatch tables), not the rule. Look at it when lint startup is tuned.
- **Python scope pass, rare differences from ruff** (found on ruff's, black's and CPython's own test files, none in the parity corpus): `F823` is reported on a `match match:` subject and on a read of a module name bound by a walrus when ruff is silent (`tests/data/cases/pattern_matching_generic.py`, `pep_572_remove_parens.py` of black); `F811` on the repeated parenthesized targets of `with a as ((x), (y))` (`preview_unpacking_parens.py`) is not reported. Cause: ruff's rules for which binding a later rebinding shadows are not fully reproduced. Fix: probe ruff on a reduced file and adjust `Model::undefined_local` and `Model::redefinition`.
- **Python `invalid-syntax` covers four of ruff's semantic syntax errors** (duplicate parameter, repeated keyword argument, `nonlocal` at module level, `await` outside an async function). Not reported: `async for` / `async with` outside async functions, rebound comprehension variables, duplicate type parameters, `match` pattern errors, `__debug__` writes, name used before `global` / `nonlocal`, starred assignment targets and expressions in invalid places. None is in ruff's default set as its own rule; the corpus has no finding of them. Fix: one native check each in `rules/stmts.rs::invalid_syntax`.
- **`finish.sh --all` on a clean tree fails the bench job with exit 2**: not reproduced by reading. `finish.sh` and `bench.sh` both take `HEAD^` as the base when the tree is clean and HEAD is the merge-base, and the CI run checks out a snapshot commit that differs from the base, so "nothing to compare" (exit 2 at `bench.sh` line 75) should not trigger there. Other exit-2 sites of `bench.sh`: the usage `case` (an argument it does not know) and a missing valgrind. Next: run `scripts/finish.sh --all` on a clean tree once and read the job log (`gh run view ID --log-failed`) for the line that exits 2.
- **C/C++ `unreachable-code` false positive on lowercase-macro case labels**: a case body that is a lowercase macro call such as `read_sysreg_case(X);` (no `case` keyword visible) reads as a statement after the previous `return`/`break`. Fix: treat a macro-like call statement after a terminator inside a `switch` body as a possible label in shared role precision, or classify via the directive-aware macro pass (Phase 2).
- **Java `curly` fixture re-blessed with narrower spans** (`tests/rules/java/curly/bodies.java`, in a2102af9, the Java Checkstyle step): 12 caret lines shrank (`^^` to `^`) while the test still passes, so the rule's reported span changed with the shared declaration rows. Check: restore the fixture from a2102af9^ and run the test; if it fails, decide which span is right and fix the rule or keep the new fixture.
- **`sudsy format` rejects `tests/conformance/corpus/json-real/vscode-extension-samples/product-icon-theme-sample/theme/v1-product-icon-theme.json`**: `12:21: trailing commas are not allowed in JSON (use the jsonc dialect) (and 1 more)`. The file has a trailing comma after `"style": "normal",` and a `.json` name, so it is JSONC in practice (VS Code reads it so). Not a formatter fault; decide whether the corpus run should treat it as JSONC or skip it as invalid.
- **HTML: Hugo shortcodes are refused**: `<p>&copy; {{< year >}}</p>` gives `raw character in text`; Prettier formats it as text (13 real-world files, `hugo-shortcodes`).
- **SQL: 9 real-world files that sqlfluff parses are syntax errors for Sudsy** (`scripts/parity.sh coverage sqlfluff`, proof run): tsql `sp_RestoreScript.sql` (line 190, `FETCH NEXT FROM c INTO @a, @b` then `END`), `sp_Blocked_Process_Report_Viewer.sql` (line 315), `udf_Haversine.sql` (MySQL `CREATE FUNCTION f (a DOUBLE) RETURNS DOUBLE DETERMINISTIC` in a tsql folder), three postgres `dolphinscheduler_ddl.sql` upgrades (`d//` after `$$ LANGUAGE plpgsql;`), `udf_SeeAccessControlChanges.sql`, `udf_SeeDatabaseObjectChanges.sql`.
- **Go `unused-parameter` reports a parameter that an index chain reads** (tree-sitter-go reads `a[i][j]` as a generic type instantiation, so the operands are `TypeIdent` tokens, which the scope rows do not count as reads). Smallest input: `func f(h [][]int, i, j int) { h[i][j] = 1 }` reports `h`, `i` and `j`; found in `go/src/crypto/internal/fips140/mldsa/mldsa.go:762` (`h[i][y[idx]] = 1`) and `kubernetes/staging/src/k8s.io/dynamic-resource-allocation/api/types.go:244` (`m.Nested[name.Domain][name.Identifier]`, where `name.Domain` is a qualified type to the parser). Two in 20,580 findings. Fix: make the operands of a `TypeInstantiationExpression` and `TypeArguments` reads (the scope rows need a way to name `TypeIdent` tokens as reads without declaring them in `ParameterDeclaration`: a token selector by kind, shared); counting `PackageIdent` as a name makes `func(net, addr string) (net.Conn, error)` read its parameter `net` (26 findings of revive lost), so it is not the fix.
- **C/C++ `z = a*[] { return 1; }();` prints `a *[]`** (`crates/lang-cpp/tests/cpp.rs`, the `pointer_name` set holds `Lsqb` so that `for (auto&& [_, i] : f())` keeps `&& [`): a `*` before a lambda introducer reads as a pointer declarator. Fix: tell a structured binding from a lambda by the tree (a declaration has a type before the `[`).
- **C/C++ harness shape check rejects `##` inside a `case` label** (`case X##_A:` formats at run time, the generated `CaseClause` production has no `HashHash` part). Fix: allow `#part*` in the production without breaking `Colon`.
- **C/C++ macro bodies keep the line breaks the author wrote inside a statement**, clang-format joins them (about 30 files, `linux-kfifo.c` among them: `(\` newline `(data)[...] =` ...). Fix: a payload mode of `directive-payload-layout` that drops the source breaks inside a statement before the lines are fitted.
- **`sudsy lint` and `sudsy format --check` keep every file of the run in memory** (CMake corpus of 9,036 files, 22.8 MB of text, debug build, `/usr/bin/time -v`: 44 MB for one file, 78 MB for 300 files, 497 MB for the whole corpus with `format --check`, 497 MB for `lint` with no rules on, 764 MB for `lint` under `preset:cmake/cmake-lint`). The cost grows with the number of files, not with the language: `cli/src/lint.rs` `collect` and `format.rs` hold the loaded `File`s, their text copies and the memoized queries of `core-incremental` (parse tree per file, token-dense for CMake: a name, `(`, each argument and each blank is a token) until the run ends. Not profiled to the allocation; the fix is shared (drop the tree after the file's last query, or run files in chunks), so no CMake change. Smallest input: `sudsy lint` over a folder of a few thousand `CMakeLists.txt` files.
- **Go `unused-parameter` reports `stateError(s *scanner, c byte)` that revive does not** (`go/src/encoding/json/scanner.go:588`: `c` is unused and revive 1.17.1 reports nothing of any rule in that file's function; one extra in the 25 unclassified). Named gap: the cause on the revive side is not known.
- **Python and Ruby `no-empty-catch` ignore `comment_handles`**: `try:\n    run()\nexcept Exception:\n    pass  # ignore` and `begin\n  run\nrescue\n  # c\nend` are reported, while JS `catch (e) { /* ignore */ }` and Java `catch (Exception e) { /* c */ }` are not (default `comment_handles: true`). Cause not found; probably the comment is not a child of the clause's `body` field in those grammars. Fix: make the `body` field cover the comment, or let the shared rule look at comments between the clause's tokens, and add both inputs as fixtures.
- **Markdown `no-trailing-whitespace` reports the two-space hard line break** (`a  \nb`) and trailing spaces inside fenced code. The rule treats every language alike. Fix: let a language mark tokens or lines that are exempt (a hard break is meaning), as a kind set in `lang.yaml`.
